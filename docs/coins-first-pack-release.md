# /coins и первый пакет — 2 октября 2026

Рабочая копия: новый первый экран, 500 VC за 129 ₽, обычные пакеты карточками,
компактные баланс/ежедневный бонус, подписки ниже, FAQ и поддержка.
RU/EN, оценка числа ответов по актуальной выбранной/базовой модели из API.
Купленные VC не сгорают; пакет не включает подписку, RAG-права или аватары.
Реальная прибыль и рост конверсии пока не измерены.

## Правила первого пакета

- Пакет ID 7: 500 VC / 129 RUB, без Recurring. Доступен до первой оплаты:
  PaymentEvent или историческая Transaction типа purchase/subscription закрывают
  возможность нового резерва. Бесплатные бонусы/подарки её не закрывают.
- Авторизация и подтверждённый email обязательны перед созданием checkout.
- FirstVcPurchase: одна запись на User, уникальный invoiceId. Резерв и проверки
  выполняются под блокировкой User; параллельные запросы возвращают один invoice.
  Повторное оформление обновляет подпись текущего SuccessUrl2/языка, сохраняя invoice.
- Уже выданный, ещё неоплаченный резерв можно завершить даже после иной покупки:
  оплаченный счёт не должен терять обещанные VC. Второй резерв не выдаётся.
  Резерв без TTL: для отмены/замены истёкшего у провайдера invoice нужна отдельная
  операторская процедура со сверкой платежа; не удалять его автоматически.
- Webhook проверяет подписанные packageId/offer/VC, точную сумму и владельца
  зарезервированного invoice. PaymentEvent, начисление, статус completed,
  Transaction и Notification — одна транзакция. Повторы дают один grant.
- Для обычных новых пакетов сервер тоже задаёт VC и цену; desc/price/vc из клиента
  не определяют сумму начисления. Уже выданные старые checkout без packageId
  продолжают проходить прежнюю проверку подписи.
- Метрика: обычная vc_purchase_success с server-confirmed amountRub=129,
  без новой цели. Возврат на сайт сам по себе не считается подтверждением.

## Контекст персонажа

Баланс в чате ведёт на /coins?characterId=<id>. Допускается только внутренний ID.
Имя/аватар загружаются через API с существующими проверками public/owner.
Неподтверждённая оплата показывает pending. После подтверждения отображается
кнопка возврата к тому же персонажу; автоматического перенаправления нет.
При входе callbackUrl сохраняет coins/characterId; при смене аккаунта состояние
магазина сбрасывается. Повторный checkout не создаёт новый invoice.
