# Прокси для LLM-промпта аватара

Новый `avatar_prompt` уже использует общий транспорт: `avatarPromptWriter.writeAvatarPrompt` → `aiTextClient.serviceChatPost` → `aiCostTelemetry.meteredPost` → `deepinfraNetwork.deepinfraAxiosOptions`. При `MEMORY_AI_PROVIDER=deepinfra` и заданном `DEEPINFRA_PROXY_URL` он отправляется на DeepInfra через существующий HTTPS CONNECT agent. Отдельного адреса прокси или нового ключа для аватарного LLM не требуется. Флаг `AVATAR_PROMPT_LLM_ENABLED` включает сам генератор промпта.

Проверена полная цепочка от реального генератора промпта до конфигурации Axios: модель Mistral Small 3.2, ключ DeepInfra вместо legacy-ключа, общий повторно используемый агент, таймаут 10 секунд, максимум 450 токенов, запрет перенаправлений и стандартная проверка TLS. При ошибке/таймауте/неподходящем ответе сохраняется резервный шаблон. Некорректный адрес прокси приводит к отказу до отправки; прямого обходного запроса нет. Изображение-референс не передаётся текстовой модели.

Добавлено техническое событие `[AvatarPrompt] request completed` с `purpose=avatar_prompt`, `networkRoute=proxy`, моделью, статусом, длительностью и идентификаторами запроса. При ошибке маршрут также виден в существующем `service attempt failed`. Содержимое карточки, готовый промпт, референс, ошибки провайдера, адрес прокси и ключи не логируются.

Новая команда `npm run verify:avatars:proxy` проверяет эту цепочку, успешную генерацию, резервный шаблон, диагностику, учёт стоимости, отключённый флаг и независимость legacy-провайдера. Проверки используют только вымышленные данные, имитацию Axios и учёт в памяти — без сети, рабочей базы и платных вызовов. Сама генерация изображения в Kie сохраняет свой прежний транспорт; изменение относится к предварительному текстовому запросу DeepInfra.
