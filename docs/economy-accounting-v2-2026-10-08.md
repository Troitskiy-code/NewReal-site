# Учёт себестоимости v2 — 8 октября 2026

Реализована новая схема учёта. Выкладка, production-миграция и сверка production
AiCostEvent с кабинетом не выполнялись. Цены, VC, квоты аватаров и платежи не менялись.

## Смысл стоимости

- `chat_completions`: `usage.cost` сохраняется в `providerCostNative` с валютой USD
  и семантикой `gateway_total_usd`. Документация caching описывает его как итоговую
  сумму с наценкой и скидкой кэша. Если задан положительный `AI_COST_USD_RUB`,
  пересчёт `usage.cost × курс` даёт **оценку** `chat_usd_estimate`; дополнительных
  10% нет. Настроенный курс не объявляется фактическим историческим курсом шлюза.
- Это относится и к служебным запросам к Chat Completions: intent, память,
  summary, события и промпты персонажей.
- `embeddings`: исходный cost сохраняется, но его валюта и включённость наценки
  остаются `null` / `unverified`. Оценка — входные токены × итоговая RUB/1M цена
  каталога. Выходных токенов нет. Курс чата на этот путь не влияет.
- При отсутствии курса чат тоже использует RUB каталог. При отсутствии ставки
  стоимость неизвестна. Нулевой native cost сохраняется для сверки и не означает
  бесплатный вызов.
- `cached_tokens` / `cache_write_tokens` — части входных токенов, не прибавляются
  к prompt_tokens. Они сохраняются раздельно. Каталожная оценка не учитывает скидку
  чтения кэша; при ненулевых cache-write без известной ставки оценка по каталогу
  отсутствует, так как запись может быть дороже обычного входа.
- Пересчёт/каталог не записываются в `reportedCostRub`. Старые значения этого поля
  сохраняются без изменения, но выводятся как `legacyUnverifiedRub`, а не как
  подтверждённые списания.

Официальные источники:

- [Чат, кэш и стоимость](https://kodikrouter.ru/docs/caching).
- [Итоговые цены каталога и наценка](https://kodikrouter.ru/pricing).
- [Заголовок шлюза](https://kodikrouter.ru/docs/gateway).
- [ID тела ответа провайдера](https://kodikrouter.ru/docs/examples).

Формулировка caching об «авторитетной стоимости провайдера» неоднозначна рядом
с определением итоговой стоимости чата. Для финальных расходов используется
рублёвая выписка; семантика rerank/Decisions не применяется ко всем endpoint.
Пути `cost_rub` / `cost_usd` в API-ответе не установлены и не угадываются парсером.

## Сверка без записи в БД

`npm run economy:costs` формирует JSON `schemaVersion: 2`. Соединение берётся
только из явно заданного `COST_REPORT_DATABASE_URL`, `.env` не загружается.
Транзакция READ ONLY, timeout 30 секунд; до 200000 событий за отчёт.
Период: `COST_REPORT_DAYS` (14 по умолчанию) или `COST_REPORT_FROM` /
`COST_REPORT_TO` в ISO с явным Z/смещением. Слишком большой период/число строк
отклоняются вместо неполного отчёта.

Для сверки дополнительно указать:

- `KODIK_COST_EXPORT`: путь к JSON экспорту истории KodikRouter вне Git;
- `KODIK_COST_API_KEY_NAME`: точное имя ключа в экспорте, например `NewReal Chat`
  (это имя, не секрет);
- `COST_REPORT_OUTPUT`: путь для агрегированного отчёта, если нужен файл.

Сопоставление только по точному совпадению экспортного `request_id` с отдельно
сохранёнными `providerRequestId` (заголовок шлюза) или `providerResponseId`
(JSON/SSE id). Проверяются фактическая модель и имеющиеся измеренные токены.
Совпадение времени/токенов без ID не подтверждает связь. Исторические response ID
не выдумываются. Если ID повторяется у разных событий/строк либо два ID указывают
на разные списания, расход остаётся несопоставленным.

Повтор одной и той же строки выписки с тем же ledger id не удваивает расход.
Проверка уникальности ID запроса учитывает также строки с нулевой/отсутствующей
суммой и статусом ошибки. Они не могут скрыть неоднозначность другой строки.
Чужое имя ключа, отрицательная/невалидная стоимость и несоответствие модели
не подтверждаются. Нулевые/отсутствующие суммы показываются отдельно; не
объявляются бесплатными. Суммирование рублёвой выписки — десятичное,
`confirmedCostRubExact` сохраняет точную строковую сумму.

Подтверждённая экспортом RUB сумма заменяет оценку того же события в отчёте,
не складывается с ней. Сам журнал БД не изменяется. `reportedCostRub` в JSON v2
— совместимый псевдоним **подтверждённого** итога, не старого поля БД.
Всегда раздельны confirmed / estimated / unknown и исключённые legacy суммы.

Итоги всего экспортного файла могут охватывать другой период, чем AiCostEvent.
Часовой пояс экспорта без смещения не угадывается; общий `exportSuccessRub`
не подставляется вместо стоимости событий в периоде. Из отчёта исключены
пользователи, emails, диалоги, секреты и исходные строки экспорта.

## Экономический калькулятор

`ECONOMY_COST_REPORT` принимает только JSON v2. Средний сценарий использует
затраты и реально списанные VC по тем же покрытым платным чатам. Гостевые и
нулевые VC-вызовы учитываются в общей себестоимости отчёта, но исключаются
из платной цены запроса. Требуется ≥90% покрытия usage и стоимости для каждой
платной модели. Этот порог не доказывает достаточность выборки или прибыль.

Low/high/stress — прогнозы по p50/p95 и каталогу, а не суммы выписки.
В среднем сценарии оценки также могут присутствовать; разделение подтверждений
и оценок сохраняется в metadata. Retry/RAG, CAC, налог, возвраты и инфраструктура
остаются предположениями. Отчёт не объявляет измеренной маржой все расходы сайта.

## Выкладка

Применить **до кода** миграцию `20261008160000_ai_cost_accounting_v2` обычным
порядком деплоя Prisma. Она добавляет второй ID, endpoint, версию/семантику учёта,
cache-write и индексы. Существующие строки сохраняют `accountingVersion=1`;
новые строки явно записывают 2. История и ранее начисленные VC не изменяются.
Runtime роль не должна получать DDL. Сборщик при сбое записи не ломает AI-ответ,
но полноту сбора после релиза нужно проверить отдельно.

`KODIKROUTER_USAGE_COST_CURRENCY` больше не читается: общая настройка не может
задавать семантику разных endpoint. Обязательных новых runtime переменных нет.
`AI_COST_USD_RUB` опционален для чатовой оценки; без него используется RUB каталог.
Не подставлять условный курс или сегодняшний курс для исторического списания.
Новых cron нет. Production миграцию/курс/покрытие нужно проверить оператору.
