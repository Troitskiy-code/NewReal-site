# Единственная система RP-промптов — v2

Дата: 12 октября 2026. Изменения подготовлены в рабочей копии. Коммит, push, деплой и SQL в production в этой задаче не выполнялись.

Предпосылка: до этой задачи в production уже были переведены 229 карточек и 101 состояние чата. Вместе с ранее созданными карточками там было 237 карточек v2; проверка массового перевода описана в `prompt-bulk-rollout-execution-2026-10-12.md`. Текущая задача удаляет программные пути старой сборки, а не повторяет массовый перевод.

## Поведение сайта

- Создание персонажа, вселенной и группы всегда сохраняет `promptBuilderVersion: 2`. Произвольный `systemPrompt` больше нельзя импортировать через создание/редактирование карточки; переданный клиентом номер версии не может создать v1.
- Обычный ответ, продолжение, регенерация и гостевой ответ используют один сборщик `chatSystemPrompt.ts` (`rp-v2.1`). Старый текст и архив не выбираются для исполнения. `RP_PROMPT_V2_ENABLED`, даже установленный в `false`, больше не влияет на поведение.
- Новое состояние чата создаётся с `builderVersion: 2`. При встрече старого значения оно обновляется до 2 без удаления сообщений и памяти; выбранный ранее тип истории сохраняется.
- При входе и переносе гостевых сообщений создаётся/обновляется состояние v2. Существующая история пользователя сохраняет свой тип; новая история получает гостевой тип.
- Редактор не загружает и не отправляет архивные инструкции/номер сборщика. Разделы переключения, подтверждения перехода и отката удалены. Стиль, сведения карточки, участники и предпросмотр остаются.
- В настройках чата есть только «Тип и правила истории» с выбором типа. Новый `/api/chat/[id]/story-settings` возвращает только `mode`, проверяет сессию, доступ к карточке и заполненность группы. Запрос на выбор версии отклоняется.

## Что удалено и закрыто

Удалены `chatSystemPromptV1.ts`, неиспользуемый AI-генератор готовых промптов, прежнее добавление личности поверх старого текста, политика rollout, модуль массового перевода/отката, его админ-страница, публичный rollout API, hook и интерфейс выбора версии. Удалены команды проверки выведенного из эксплуатации механизма перевода. Проверки действующего сборщика обновлены.

Старые адреса `/api/characters/[id]/prompt-version`, `/api/chat/[id]/prompt-version` и `/api/admin/prompt-migration` оставлены как короткие ответы HTTP 410 без доступа к БД и без исполнения перевода/отката. Неиспользуемый `/api/chat` с передачей произвольного промпта в MuAPI также возвращает 410. Действующий чат использует `/api/chat/[id]`.

Архивы `systemPrompt`/`legacyPromptArchive`, исторические метки, снимки массового перевода и старые SQL-миграции сохранены в БД/истории репозитория. Это данные для сохранности, а не действующая реализация v1. Обычный API карточек не раскрывает архивные тексты даже владельцу; редактор их не использует.

## База и переменные

В `schema.prisma` значения по умолчанию для `Character.promptBuilderVersion` и `ChatPromptState.builderVersion` изменены на 2. SQL `prisma/migrations/20261012220000_prompt_v2_defaults/migration.sql` содержит только два `ALTER COLUMN … SET DEFAULT 2`. Он не меняет существующие строки, архивы, сообщения или память. Повторное применение проверено в PGlite.

До применения этих двух команд новый код также создаёт v2: номер явно передаётся во всех действующих путях создания состояния/карточки. SQL нужен для согласования значений по умолчанию БД и Prisma, включая будущие внешние вставки. Production SQL в этой задаче не выполнялся. При ручном применении использовать адресный SQL после бэкапа; не запускать все исторические миграции с нуля в production без истории Prisma.

После выкладки можно удалить `RP_PROMPT_V2_ENABLED` и, если ещё есть, `CHARACTER_PROMPT_MODEL` из переменных сервера. Новых переменных, cron или платных действий для этой задачи нет. В `.env.example` эти неиспользуемые настройки убраны. Старую открытую страницу редактора/чата после выкладки нужно обновить.

## После выкладки

Проверить обычный ответ, продолжение и регенерацию существующей истории, затем создать новую карточку и открыть её чат. Проверить, что редактор и настройки чата не предлагают выбор версии. Это ручная production-приёмка поведения модели: локальные проверки не измеряют литературное качество живых ответов.
