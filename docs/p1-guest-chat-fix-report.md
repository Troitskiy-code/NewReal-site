# P1: гостевой чат и продолжение после входа

Проверено 2 октября 2026. Изменения относятся к рабочей копии, не к production.

## Изменения

- Переходы claim/retry/fail/persist/finalize/renew/transfer используют одну блокировку строки гостевой сессии в коротких транзакциях PostgreSQL. AI-вызов вне транзакции.
- Возврат лимита привязан к attempt и успешному изменению pending → failed. Проигравший retry не оставляет лишнее резервирование.
- Сообщение пользователя и userMessageId сохраняются атомарно; retry использует прежнюю запись. Конкурентное создание самой сессии не падает на unique constraint.
- Все операции подготовки после claim покрыты recovery. Истёкшие попытки восстанавливаются при GET, новом claim и transfer; живые продлевают lease каждые 20 секунд. Чтение гостевого AI-потока ограничено 120 секундами и отменяет зависшее тело ответа.
- Клиент ожидает transfer с ограниченным backoff, показывает ожидание и кнопку повтора. Отправка нового сообщения блокируется до переноса. Уход со страницы/смена аккаунта отменяют запросы и публикацию старого результата.
- Safe callback принимает /ru/chat/... и /en/chat/...; внешние адреса и auth-страницы остаются запрещены.

## Проверки

`scripts/verify-guest-p1.mjs`: 33 положительные проверки на отдельном PostgreSQL 18.4 и Playwright/Edge. .env не используется для подключения к БД; кластер создаётся в новой временной директории на свободном порту. Тест не останавливает процессы по порту и не затрагивает production.

Проверены конкурентные claim/retry/refund/persistence/transfer, fence старой попытки, восстановление истёкшей lease, rollback сообщения при настоящем отказе UPDATE через PostgreSQL trigger, ошибки подготовки модели/истории в настоящем обработчике и отмена зависшего потока.

Браузер: guest → send → refresh → credentials login → ожидание текущей генерации → автоматический transfer → refresh → logout. Задержанная генерация завершается через 5 секунд после появления ожидания. Проверены очистка гостевой cookie, отсутствие дублей и изоляция истории после logout. AI-ответ синтетический; запросы браузера к внешним хостам заблокированы, счётчик 999001. Google OAuth и регистрация с доставкой письма не проверялись.

Другие проверки: TypeScript — exit 0; ESLint изменённых файлов — 0 errors, 2 прежних предупреждения img; verify:p0-p1 — 40; verify:p0-security — 109; verify:metrika — 91; git diff --check — exit 0.

Production build с синтетическими env — exit 0: Prisma Client сгенерирован, Next/Turbopack и TypeScript завершились. Осталось прежнее предупреждение трассировки next.config/currencyRates. Изолированная несуществующая build-БД дала безопасные диагностические сообщения sitemap/slug; это не проверка живой БД. После завершения тестов приватные Next/PostgreSQL процессы остановлены.

Воспроизводимый тест запускается командой `npm run verify:guest-p1` с GUEST_TEST_RUNTIME, указывающим на отдельную временную установку embedded-postgres. GUEST_TEST_BROWSER=1 включает браузер; GUEST_TEST_BROWSER_CHANNEL=msedge использует установленный Edge. В тестовой схеме vector заменён Bytes: RAG/pgvector этой проверкой не принимается.

## Границы закрытия

Закрыты четыре замечания гостевого блока из второго независимого ревью и проверена браузерная цепочка. Общий P1 остаётся открыт: поддержка/outbox, общий rate limit, webhook, миграционный upgrade/baseline, runtime DDL и production-приёмка — отдельные задачи. Старые pending/payloadHash миграционной истории этим исправлением не backfill-ятся. Цены и VC не менялись; production, миграции, коммит и push не выполнялись.
