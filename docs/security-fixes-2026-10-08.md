# NewVerse: исправления безопасности после аудита

Дата проверки: 8 октября 2026. Основание — первый приоритет и SEC-01/02/03 из `project-audit-2026-10-07.md`. Первичная проверка выполнена до commit/push; публикация разрешена владельцем отдельным последующим запросом. Production, реклама, цены и схема production-БД в рамках проверок не изменялись.

## Статус

SEC-01 и SEC-03 исправлены в коде и проверены отдельными runtime-пробами. Для SEC-02 обновлены доступные исправленные зависимости; production-аудит показывает 0 известных уязвимостей. Полный аудит всё ещё показывает 5 high в одной dev-цепочке lint, для которой пока нет совместимого опубликованного исправления. Поэтому нельзя утверждать, что полный dependency audit зелёный или что вся безопасность production окончательно закрыта.

Ротация ранее раскрытых credentials остаётся отложенной по решению владельца. Реальное восстановление production-backup не подтверждено этим заданием. Эти статусы сохранены, несмотря на успешные проверки кода.

## SEC-01: произвольная серверная загрузка

- `GET /api/download` теперь возвращает 410 и `DOWNLOAD_PROXY_DISABLED`, с `Cache-Control: no-store`. В обработчике нет сетевых запросов или перенаправления на предоставленный URL. Авторизация больше не нужна для отклонения: любой запрос останавливается до побочных действий.
- Старые ImageTemplate/VideoTemplate скачивают готовый результат через `downloadGeneratedMedia.ts` непосредственно браузером, без credentials. Поддержаны HTTPS и растровые/video data URL, ограничение 100 MiB проверяется и по заголовку, и во время чтения потока. HTML/SVG и неподдержанные протоколы отклоняются. Если провайдер запрещает CORS, открывается оригинал с `noopener,noreferrer`; автоматическое сохранение в этом случае зависит от провайдера и разрешений браузера.
- Аналогичный обход в референсе аватара закрыт: `/api/generate-avatar` принимает загруженный raster data URL до 5 MiB, отклоняет внешние URL до резервирования лимита и вызова провайдера. `createya.convertImageToPNG` также не скачивает URL референса. Обычная загрузка файла в CharacterForm сохранена.

## SEC-03: ошибки, старый экспорт и приватность

- `POST /api/app-instances/export` возвращает 410 и `SERVER_EXPORT_DISABLED`. Удалён старый серверный код копирования исходников, передачи env, создания GitHub/Vercel проектов и файловой очистки. Эта возможность старого конструктора отключена целиком.
- Неизвестные caught errors из API и серверных помощников передаются в `errorLog` через `toSafeDiagnostic`. Ответы API не отражают произвольные `Error.message`, Prisma/axios payload и строки ошибок. Обработаны и старые billing/generation/creations/admin пути, а не только маршрут аватара.
- Валидация использует отдельный `ClientInputError`: контролируемые сообщения о неверных данных остаются 400; неизвестный сбой не может выдать себя за валидацию по совпадению текста и получает общий ответ 500.
- Чистые клиентские/shared помощники chatStream/retry используют `safeErrorFields`, без импорта серверного Logtail в браузер.
- Для API добавлена lint-проверка, запрещающая прямые `console.error/warn`. Общая обёртка console не вводилась.
- Удалён глобальный public-cache override для приватных аватаров. Владелец получает `private, no-store`, другой аккаунт — 404, публичный растровый аватар остаётся кэшируемым. SVG/HTML/неизвестный data MIME не выдаётся из avatar endpoint; добавлен `nosniff`.
- Из серверных file traces исключены `.env`, `.env.*`, `.git`. Динамический runtime-кэш валют больше не заставляет Turbopack включать весь проект в трассировку. SQL адресной миграции поддержки по-прежнему включён.

## SEC-02: зависимости и применимость

Установлены и закреплены в lockfile: Next.js 16.4.0, eslint-config-next 16.4.0, NextAuth 4.24.15, axios 1.20.0. Выполнено совместимое обновление транзитивных пакетов без `audit fix --force` и без downgrade Next.

Проверены первичные advisory: [Next AVIF](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4), [Next ImageResponse](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j), [NextAuth email sign-in](https://github.com/advisories/GHSA-7rqj-j65f-68wh). Использование ImageResponse и email-provider magic link в проекте не обнаружено; обновление всё равно выполнено. Исходный аудит не доказывал эксплуатацию этих advisory на сайте.

Результат `npm audit --omit=dev --json`: 0 total, 0 critical, 0 high. Полный `npm audit --json`: 5 high, 0 critical, exit 1. Все пять записей принадлежат одной цепочке `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`. Для [braces / GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) опубликованной patched version нет. npm предлагает переход на eslint-config-next 14.2.35; такой несовместимый downgrade не применялся.

Проверенный вызов glob в Next ESLint берёт шаблоны из `settings.next.rootDir` конфигурации lint. В нашем конфиге этот параметр не задан; пути запросов сайта туда не передаются. Цепочка отсутствует в production dependency audit. Это ограничение применимости, а не исправленная версия braces и не основание скрыть полный audit fail. Не следует принимать внешние glob-patterns в конфигурацию lint; требуется повторная проверка после появления исправления upstream.

## Что ещё требуется для production

1. Выпустить подготовленные изменения вместе с package-lock.json на Relaxdev. Для этих исправлений не нужны новые env-переменные или новая миграция БД.
2. После выпуска проверить настоящий credentials/Google-вход, показ публичного и приватного аватара, загрузку референса файлом и поддержку. Старые download/export endpoints должны возвращать 410. Live OAuth/почтовая конфигурация не подтверждается изолированными тестами.
3. Получить подтверждение свежего production-backup и тестового восстановления в отдельную БД от Relaxdev. Проверки миграций на временных фикстурах не подтверждают пригодность production-backup.
4. Остаточный dev advisory braces и общий lint debt остаются в списке контроля. Отложенная владельцем ротация не выполнена.

Ручные действия отдельно сообщаются владельцу в чате; этот документ не заменяет такое сообщение.
