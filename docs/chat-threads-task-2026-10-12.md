# Задание: независимые истории с одним персонажем (ChatThread)

Дата постановки: 12 октября 2026. Основание: [аудит 7 октября, RET-01](project-audit-2026-10-07.md#ret-01--качество-памяти-и-несколько-историй), [модель памяти v2, разделы 3, 7, 10](memory-model-v2-2026-10-08.md). Пользователи уже спрашивали об этой функции в поддержке.

## Цель

Пользователь может вести несколько отдельных историй с одним персонажем (одиночный герой, «Вселенная» или группа). У каждой истории свои сообщения, память, сводка, персона и учёт стоимости. Пользователь видит список историй, продолжает выбранную, начинает новую, переименовывает, архивирует и удаляет историю.

Пример: с «Вампиром Лео» идут история A (война кланов) и история B (сосед, романтика). В истории B персонаж не знает ничего из A.

## Текущее состояние (проверено 12.10 по рабочей копии)

- `Message.chatId` в активном API равен id персонажа: `src/app/api/chat/[id]/route.ts:239, 255, 417`. Чтение идёт по `userId + characterId`.
- Память привязана к паре пользователь+персонаж: `Memory` и `CoreMemory` — `@@unique([userId, characterId])`; `EpisodicMemory`, `MemoryEntry` — индексы по `userId, characterId`.
- Эмбеддинги `MessageEmbedding` (1536) и `MessageEmbeddingDeepinfra` (1024) привязаны к `messageId`; поиск RAG фильтрует через сообщения — проверить фильтр в `src/lib/messageEmbeddings.ts`, `src/lib/ragRetrieval.ts`.
- Персона: `PersonaSelection @@unique([userId, characterId])`, `src/lib/personaService.ts`.
- `ChatPromptState @@unique([scopeKey, characterId])` — выяснить, что такое `scopeKey` и нужен ли разрез по истории.
- `WorldEvent` хранится на персонаже без userId — выяснить, пишется ли туда пользовательский сюжет. Если да, это утечка между историями и пользователями: зафиксировать отдельно и согласовать изоляцию.
- Гостевой чат: `AnonymousMessage`, `src/lib/anonymousChat*.ts`, `anonymousTransfer.ts`, `guestTransferRetry.ts`. При claim сообщения переносятся в аккаунт.
- Затронутые API: `api/chat/[id]` (и `messages`, `memory`, `persona`, `prompt-version`, `regenerate`), `api/chats`, `api/messages/[id]`, продолжение ответа (см. `docs/chat-continuation-fix-2026-10-09.md`), редактор памяти.
- UI: `src/app/chat/[id]`, `src/app/chats` (список чатов), страница персонажа `src/app/character`.
- Учёт: `AiCostEvent` (поле `operationId`, без привязки к истории), цели Метрики `src/lib/goalTracking.ts`, `acquisitionGoals.ts` (`chat_engaged`).

Перед изменениями заново перечитать эти места: номера строк могли сдвинуться.

## Объём

Входит этап 1 и UI этапа 4 из [модели памяти v2](memory-model-v2-2026-10-08.md#10-этапы-внедрения):

1. **Сущность `ChatThread`**: `id`, `userId`, `characterId`, `personaId?`, `title`, `status` (`active` / `archived`), `createdAt`, `lastMessageAt`. Добавить `memoryWatermarkMessageId?`, если это нужно текущей фоновой памяти, иначе оставить для этапа 2.
2. **Аддитивная миграция**: `threadId` в `Message` (или использовать `chatId` как ссылку на историю, решить и обосновать), `Memory`, `CoreMemory`, `EpisodicMemory`, `MemoryEntry`, `PersonaSelection` (или `personaId` в истории) и в остальных местах, найденных при разборе. Для каждой существующей пары пользователь+персонаж с сообщениями или памятью создаётся одна история по умолчанию, и все её записи получают этот `threadId`. Уникальные ограничения меняются с `(userId, characterId)` на `threadId` только после заполнения. Миграция идемпотентна и повторно запускаемая, большие таблицы обновлять пачками.
3. **Чтение и запись по `threadId`** во всех путях: чат, стриминг, продолжение, перегенерация, правка и удаление сообщений, RAG, сводка, core, эпизоды, редактор памяти, пересборка памяти, фоновые задачи и cron, персона. Старый ключ под флагом (например, `CHAT_THREADS_ENABLED`), чтобы можно было откатиться без отката схемы.
4. **API историй**: список историй пользователя для персонажа, создание, переименование, архив и восстановление, удаление с подтверждением. Все операции проверяют владельца. Чужой `threadId` → 404, без раскрытия существования.
5. **Совместимость адресов**: `/chat/[id]` без истории открывает последнюю активную историю (или создаёт первую). Выбранная история задаётся в URL так, чтобы не раскрывать лишнего (см. `docs/sec-04-url-privacy-2026-10-08.md`), и страницы истории остаются `noindex`.
6. **UI**:
   - в чате: переключатель или список историй и кнопка «Новая история»;
   - на странице персонажа: «Продолжить» последнюю и «Новая история»;
   - в `/chats`: показать истории (по персонажу или плоским списком с названием истории).

   RU и EN тексты, доступная разметка (подписи, фокус, Escape в модальных окнах). Стиль — токены палитры из `docs/style-redesign-2026-10-11.md`.
7. **Новая история**: пустая память, первое сообщение и начальная ситуация из карточки, как при первом входе. Персона копируется из текущего выбора, дальше меняется только внутри истории. Общий профиль между историями не вводится.
8. **Гость**: у гостя одна история. При claim гостевые сообщения становятся **новой отдельной** историей, если у пользователя уже есть история с этим персонажем, иначе — историей по умолчанию. Смешивания с существующей историей быть не должно.
9. **Учёт**: `threadId` (или его хэш) в `AiCostEvent` и в параметрах целей там, где это не нарушает приватность аналитики. Существующая дедупликация целей сохраняется: `chat_engaged` по-прежнему считается один раз по согласованному правилу. Решить и записать, на пользователя+персонажа или на историю.
10. **Списание VC и лимиты** не меняются. Создание истории бесплатно и без лимита количества, если по ходу не обнаружится технической причины его ввести.

Не входит: `MemoryFact`, `StoryEvent`, версионируемая выжимка (этапы 2–3), общий профиль `user_global`, Telegram, изменения тарифов и цен VC, экспорт и удаление аккаунта (TRUST-01).

## Ограничения и порядок работы

- Прочитать `AGENTS.md`: в проекте Next.js с изменёнными API. Перед кодом свериться с `node_modules/next/dist/docs/`.
- Production (БД, переменные, деплой Relaxdev) не трогать. Миграцию готовить в `prisma/migrations/` и проверять на временной локальной PostgreSQL. Отдельно записать порядок выкладки: бэкап, проверка восстановления, SQL одной транзакцией или пачками, флаг, деплой, смоук.
- Платных AI-провайдеров не вызывать: проверки — с подставным AI и эмбеддингами, как в существующих `scripts/verify-memory-*.mjs`.
- Коммит и push — только по отдельному разрешению владельца.
- Не ломать: гостевой чат и claim, продолжение и перегенерацию, редактор памяти, «Вселенные» и группы до 8 участников (`docs/roleplay-editor-and-groups-2026-10-11.md`), цели Метрики и учёт стоимости.

## Приёмка

Изолированные проверки (новый скрипт, например `scripts/verify-chat-threads.mjs`, плюс `npm run` в `package.json`):

1. Миграция на копии с синтетическими данными: каждая пара получила ровно одну историю по умолчанию, ни одно сообщение и ни одна запись памяти не потеряны и не продублированы, повторный запуск ничего не меняет.
2. Старый диалог открывается и продолжается без изменений для пользователя.
3. Две истории с одним персонажем не смешивают сообщения, RAG, core, эпизоды, сводку и персону — сценарий «Две истории» из `memory-model-v2` (раздел 9.2): в истории 2 «Где мы?» → Марс, без Москвы.
4. Изоляция владельцев: чужой `threadId` в любом из API → 404, без побочных эффектов.
5. Перегенерация, продолжение, правка и удаление работают внутри выбранной истории и не трогают другую.
6. Удаление истории удаляет её сообщения, эмбеддинги и память и не трогает другие истории.
7. Claim гостя не смешивается с существующей историей.
8. Возврат после перерыва открывает выбранную (последнюю) историю.
9. Выключенный флаг возвращает прежнее поведение.
10. Повторно проходят: `verify:memory*`, `verify:chat:continuation`, `verify:guest-p1`, `verify:p0-p1`, `verify:p0-security`, `verify:metrika`, `verify:economy*`, `verify:sec04`, `verify:seo`, TypeScript, lint затронутых файлов, `next build` с синтетическими env.
11. Браузерная проверка на локальной сборке: список историй, новая история, переключение, переименование, архив, удаление, мобильная ширина, RU/EN, без ошибок в консоли.

## Вопросы владельцу (умолчания, если ответа нет)

1. Лимит числа историй на персонажа — без лимита.
2. Удаление истории — необратимо, с подтверждением; архив как обратимая альтернатива.
3. Название новой истории — автоматическое («История 2» или дата), с переименованием.
4. Видят ли гости список историй — нет, у гостя одна история.
5. Учёт `chat_engaged` — один раз на пользователя+персонажа, как сейчас, чтобы не завышать цель Директа.
