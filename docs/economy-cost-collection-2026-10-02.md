## Исправленный расчёт

`npm run economy:acquisition` использует взвешенные доли запросов моделей:
средние VC и рубли на запрос считаются по одному и тому же распределению.
Входные и выходные токены имеют отдельные цены. Скачка на пороге 30% больше нет.
Проморасход добавляется к затратам; эквайринг консервативно считается с полной
оплаты. Неиспользованные сгораемые VC подписки не создают выдуманный перенос.
Для купленных постоянных VC отдельно показана оценка будущей себестоимости.

Пакет за 129 ₽ реализован как 500 VC; калькулятор использует один фиксированный
объём для всех сценариев. Его конверсия и прибыльность остаются гипотезами.
Конверсии, CAC, возвраты, налог, активные дни,
загрузка аватарного лимита и служебная нагрузка остаются предположениями.
Калькулятор без production-выгрузки не выдаёт измеренную прибыль.

`ECONOMY_COST_REPORT` позволяет загрузить JSON из `economy:costs`: модельный mix,
снимки цен и p50/mean/p95 токены. Требуется минимум 90% coverage provider usage
для каждой завершённой чат-модели и известные цены. Неполные данные останавливают
этот режим, а не превращаются в нулевую цену. Stress использует минимум
16 000 input / 1 000 output. Множители retries/служебных вызовов пока предположения;
для финансовой приёмки сверять их с отдельными фактическими строками журнала.

## Сбор затрат

Новая таблица `AiCostEvent` хранит по каждой попытке HTTP-вызова:
провайдера, запрошенную/фактическую модель, назначение, operationId,
хеш владельца, audience, тариф, токены/cached tokens, снимок VC и RUB-цен,
реально списанные VC основного чата, длительность, исход и источники цены/usage.
Финальные SSE usage кадры не суммируются повторно. Стоимость fallback-модели
не подменяется ценой первоначально запрошенной модели.

Покрыты чат/гость/повтор/продолжение, intent, память/summary, embeddings
(RAG в messageEmbeddings и semantic-dedup в memoryEmbeddings),
создание промпта, события персонажей, аватары, перевод и MuAPI submissions.
Собственные пользовательские API-ключи MuAPI исключены из затрат платформы.
Асинхронное принятие MuAPI не считается завершённой генерацией или известным
счётом. Его billing остаётся unknown до отдельной сверки.

Перевод считает Unicode code points отдельно от токенов, без текстов.
Цена по количеству символов — оценка, не usage провайдера.
Тексты диалогов, промпты, ответы, адреса почты и API-ключи журнал не сохраняет.
Номера задач аватаров связываются с резервом для операторской сверки.
Для Kodik сохраняется X-KodikRouter-Request-Id, если провайдер вернул его.
При отказе журнала безопасная диагностическая запись не прерывает ответ ИИ;
мониторить сообщения AiCost и coverage unknown/pending.

Денежные источники разделены: reportedCostRub / estimatedCostRub / unknown.
`usage.cost=0` сохраняется как native zero, но не доказывает отсутствие списания:
провайдер может биллить по своему каталогу (описано в
https://kodikrouter.ru/docs/integrations, Troubleshooting usage.cost=0).
Валюта без явной настройки не угадывается.
Cached tokens сохраняются; без отдельного cache-прайса каталоговая оценка может
завышать стоимость и не заменяет invoice.

## Аватары

Бюджет: 10% **номинальной месячной цены** плана, база 5 ₽, округление вниз:
Диалог 499 ₽ → 9 единиц; История 1 299 ₽ → 25; Вселенная 3 499 ₽ → 69.
Годовой план получает тот же календарный месячный лимит: эта формула основана
на месячной цене каталога, не на скидочной цене года / 12.
Любая модель, включая GPT Image, расходует одну генерацию аватара.
Существующий costMultiplier используется только в оценке провайдерной
себестоимости, а не в списании лимита. 5 ₽ и множители — принятая оценка,
не гарантия фактической цены всех изображений провайдера.

Резерв в `AvatarQuotaReservation` и счётчик пользователя изменяются одной
транзакцией под блокировкой User. Старый расход не сбрасывается при выкладке.
Если уже использовано больше нового лимита, новых генераций до следующего
сброса не будет. Явный отказ начального Createya run возвращает резерв один раз.
Таймаут/неизвестный исход оставляет manual_review; автоматического возврата нет.
Если картинка создана, но скачивание не удалось, оплаченный провайдерный расход
не отменяется. Активация и новый месяц защищены от возврата старого резерва.
Форма получает актуальный остаток сервера и обновляет его после ошибки.
Выбор модели не меняет количество списываемых генераций.

## Развёртывание и использование

Миграция `20261002160000_ai_cost_telemetry` должна быть применена **до кода**.
Не менять старые применённые миграции. Если Relaxdev запускает migrate deploy,
проверить лог и `npx prisma migrate status`. Runtime роль без DDL должна получить
SELECT/INSERT/UPDATE для новых таблиц (и DELETE, если оператор вводит retention).
Baseline preflight понимает теперь и CREATE TABLE без IF NOT EXISTS.

Для RUB оценок заполнить `Model.pricePer1MInput` / `pricePer1MOutput` проверенными
RUB / 1M с наценкой провайдера внутри. Для служебных моделей вне каталога можно
задать `AI_COST_RATES_RUB_JSON` формата
`{"provider/model":{"input":123,"output":456}}`; цифры здесь — пример формата,
не рекомендованный прайс. Без ставок остаются токены и unknown cost.

Только после подтверждения единиц usage.cost задать
`KODIKROUTER_USAGE_COST_CURRENCY=RUB` или USD. Для USD дополнительно требуется
`AI_COST_USD_RUB` с явно выбранным курсом. Native amount / currency / FX сохраняются.
Не ставить RUB лишь потому, что пополнение кабинета было в рублях.
Для перевода необязателен `YANDEX_TRANSLATE_COST_RUB_PER_MILLION_CHARS`, взятый
из собственного тарифа; без него цена перевода остаётся unknown.

Выгрузка read-only: явно задать `COST_REPORT_DATABASE_URL` на нужную БД,
`COST_REPORT_DAYS=14`, при желании `COST_REPORT_OUTPUT` и выполнить
`npm run economy:costs`. Скрипт не читает .env; адрес/пароль не выводятся.
Для пересчёта использовать путь JSON в `ECONOMY_COST_REPORT`, затем
`npm run economy:acquisition`. Никакой отдельный cron для этого релиза не требуется.

Pending/старые reserved и manual_review аватары проверяются по
AiCostEvent.quotaReservationId + providerRequestId в кабинете Createya.
Не освобождать неопределённые/оплаченные задачи автоматически. Для возврата
неоплаченной задачи операторская транзакция должна заблокировать User,
условно перевести reserved/manual_review → refunded один раз и уменьшить
счётчик только при совпадении lastTokenMonth с month резерва.
