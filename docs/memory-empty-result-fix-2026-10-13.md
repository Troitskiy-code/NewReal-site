# Пустой результат фоновой сводки: исправление

После предыдущего исправления JSON ответы модели успешно завершались, но `MEMORY_SUMMARY_EMPTY_RESULT` повторялся: проверка перефразировки заменяла короткий ответ объединёнными исходными цитатами, а лимит хранимой памяти отбрасывал слишком большой пункт целиком.

Теперь при превышении бюджета используются целые исходные цитаты с их авторством и статусом. Если выбранные цитаты слишком велики, допускается другая целая цитата, связанная с выбранным содержанием по существующей проверке пересечения слов. Такой резервный выбор явно обозначается как неясный. Несвязанные короткие реплики не используются для заполнения памяти. Неизвестные источники, неправильный JSON и неподдерживаемые поля по-прежнему отклоняются; все пункты проверяются до резервного выбора.

Когда безопасно сохранить нечего, фон сохраняет прежнюю память и границу обработанных сообщений. Это видимый `refresh deferred` с кодом `MEMORY_SUMMARY_NO_FITTING_SOURCE` либо именем `MemorySummaryInputError`, а не успешное обновление. Общая межпроцессная пауза составляет 30 минут; в течение неё повторных платных запросов нет. Ручное обновление продолжает сообщать об ограничении. Обычные ошибки провайдера/JSON сохраняют прежнюю обработку и паузу 120 секунд.

Подбор входного объёма ищет границы целых групп сообщений с одинаковым временем: подходящая первая группа больше не теряется из-за округления половины списка.

`render completed` содержит только количества: кандидаты, источники, замены перефразировок, отказы по бюджету, резервные цитаты, сохранённые пункты и итоговое число токенов. Текст переписки и сводок не логируется.

Проверки: 25 проверок повествования, 16 проверок фактического обновления/SQL-блокировок, 36 сценариев памяти; контекст, 58 проверок диагностики чата и линтер. Новые интеграционные случаи подтверждают сохранение сводки в пределах 200 токенов, корректную границу обработки и сохранение прежней памяти при невозможности обновления. Используются вымышленные данные и временная локальная PostgreSQL, без рабочей базы или реального AI.

Ограничение: единственное слишком большое неделимое предложение может остаться несуммированным. Оно не обрезается с риском потери отрицаний, условий или чисел; обработка откладывается с техническим объяснением.
