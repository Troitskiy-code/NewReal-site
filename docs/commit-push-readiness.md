# Готовность к commit/push — 1 октября 2026

**Можно сохранить промежуточный результат в отдельной рабочей ветке и продолжить работу после push. Нельзя назвать проект проверенным без ошибок или готовым к production.** Коммит, staging, переключение ветки и настоящий push не выполнялись.

## Проверено сейчас

- Текущая ветка `main`, upstream `origin/main`; Git identity настроена, обязательное подписание коммита не настроено.
- `git diff --check` прошёл; активных обычных Git hooks и custom hooksPath не обнаружено.
- Dry-run `git push --dry-run origin HEAD:refs/heads/codex/p0-p1-wip` прошёл. Он проверяет отправку текущего HEAD в предлагаемую ветку, а не будущего коммита с этими изменениями. Серверные проверки будущего коммита и настройки автодеплоя этим не подтверждаются.
- `.env` игнорируется. Проверка tracked/untracked файлов, не исключённых gitignore, не нашла двух прежних секретов из исходных auth/prisma, блоков private key и указанных высокодостоверных GitHub/AWS token-patterns. Это не универсальная гарантия отсутствия любого секрета. Старые значения остаются в Git history, production-ротация не выполнена.
- На момент инвентаризации 423 файла, суммарно около 21,5 МБ; отдельных файлов >50 МБ нет.
- `npm run verify:p0-p1`: 39 checks passed.
- `npm run verify:p0-p1:repro`: passed.
- `npx tsc --noEmit`: passed.
- `node --experimental-strip-types scripts/verify-robokassa-checkout.ts`: passed; тест в основном структурный и не проводит оплату.
- `npm run build`: passed на актуальном коде с синтетическими DATABASE_URL/NEXTAUTH_SECRET. Есть предупреждение Turbopack; недоступная локальная БД вызвала диагностические сообщения sitemap/DDL. Production-БД не использовалась.
- Lint перепроверен: 27 errors / 25 warnings; две ошибки относятся к изменениям поддержки и PurchaseStatusBanner, остальные встречаются в базовых версиях проблемных файлов.

## Что допускается отложить после сохранения в Git

Известные ошибки можно сохранить как явно обозначенную незавершённую работу, если эта ветка не выкатывается в production. Список: `docs/p0-p1-second-independent-review.md`. При чтении актуального кода подтверждено, что обе гонки quota и неполное логирование ещё присутствуют. Сохраняются непройденная браузерная цепочка, миграции/production-ротация и прочие ограничения ревью.

## Что мешает выпуску

Ошибки безопасности/гостевого лимита, красный lint, незавершённые проверки auth/payment/support и неподготовленный полный миграционный путь. Для production потребуются новые таблицы и env, cron/worker и ротация секретов. Git push не выполняет необходимые миграции автоматически. Настройки RelaxDev/Git-интеграции из этой проверки не известны; push в `main` может запускать выкладку.

## Рекомендуемый способ сохранения

Использовать ветку `codex/p0-p1-wip`, убедившись, что её push не запускает production-выкладку. Включить **и новые**, и изменённые исходники: aliases, helper-файлы, миграции и тесты сейчас untracked. `git commit -am` их пропустит и может оставить неполный проект.

Перед коммитом просмотреть staged file list и `git diff --cached --check`; локальные env, node_modules и .next не включать. Сборочные и тестовые логи не обязательны для дальнейшей разработки; можно включить компактные отчёты и необходимые fixtures. Не маркировать коммит как завершённое исправление всех P0/P1.

После push продолжать работу в той же ветке. Merge/deploy выполнять после исправлений и проверки миграций. Успех dry-run не гарантирует отсутствие всех серверных правил или ошибок будущего коммита.
