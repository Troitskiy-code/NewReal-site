# Третье независимое ревью Метрики

Дата: 1 октября 2026. Проверена текущая рабочая копия. Код приложения, commit/push, production, реальные покупки и боевой счётчик не затрагивались.

Вердикт по четырём остаточным замечаниям второго ревью: исправления подтверждены. Новых блокирующих P0/P1 в проверенных изменениях не обнаружено. Это приёмка указанных исправлений в коде, а не подтверждение production-релиза или доставки конверсий в кабинет Яндекса.

## Независимое подтверждение

Новый `docs/metrika-third-review-probe.cjs` использует fixture второго ревью, но проверяет корректное поведение, а не наличие старых дефектов. Исполняется настоящий runtime; storage, часы, API и Яндекс подставные. Никаких сетевых запросов или БД.

1. **Полный отказ localStorage, без Web Locks.** С рабочим sessionStorage статус запрошен, invoice подтверждён, цель отправлена один раз. Повторный poll и reload с тем же sessionStorage не отправляют завершённую цель снова. Проверена и конкуренция в одной вкладке: второй poll не делает параллельный запрос статуса.
2. **Устаревший dispatched / новый timeout.** Пять poll дают одну дополнительную отправку; attempts достигает 3. Новый runtime после reload не повторяет отправку, shouldContinuePolling возвращает false.
3. **Смена владельца in-flight операции.** Проверены три поздних исхода запроса A после logout → login B: обычный ответ fetch, ответ json после fetch и отклонение fetch. Ни один не пишет запись или durable key пользователя B.
4. **Сессия баннера.** Новый runtime той же вкладки с тем же sessionStorage восстанавливает текущий возврат. Новая вкладка с общей localStorage и новым sessionStorage не показывает прошлую покупку. A → logout → A без query тоже даёт пустой баннер.

Результаты: `docs/metrika-third-review-probe.json`, `allSecondReviewFixesVerified=true`.

## Границы приёмки и выпуска

- Заявленные Cursor 18 браузерных проверок в этой итерации независимо не повторялись: в workspace уже работает другой dev-сервер на 4027. Чужой процесс не останавливался, неизвестное окружение существующего сервера не использовалось.
- Полная сборка в этом ревью не повторялась; типы проверены.
- PGlite подтверждает SQL конкретной additive-миграции, но не запуск production Prisma migrate deploy и не настоящую цепочку webhook → БД → browser.
- Доставка целей в кабинет Яндекса не проверялась. Callback API и очередь браузера не заменяют проверку отчётов кабинета.
- Без Web Locks и записи межвкладочного lease действует только блокировка в пределах вкладки. Ограничение явно указано в runtime/отчёте; exactly-once во внешней аналитике не обещается, особенно при потере callback.
- Production-ротация P0 остаётся pending у оператора. Аналитическую миграцию нужно применять до выкладки кода, читающего/пишущего новые поля.

Код исправлений четырёх замечаний можно принять. Для утверждения о готовности всего production отдельно завершить ротацию, миграцию, выпускные проверки и проверку кабинета Метрики.
