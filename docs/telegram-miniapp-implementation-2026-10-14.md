# Telegram Mini App NewVerse без покупок: реализация

Дата: 14 октября 2026. Задание: [telegram-miniapp-task-2026-10-14.md](telegram-miniapp-task-2026-10-14.md).
Обновлено: 15 октября 2026. Код совмещён с локальным `main` (`1610674`) и перенесён в основную рабочую папку. Владелец разрешил коммит и push; включение Telegram выполняется отдельно. Production, Relaxdev, Adminer, @BotFather и Метрика не открывались. Платные AI-провайдеры не вызывались, внешние утилиты не скачивались (для браузерных проверок использован установленный Microsoft Edge).

## Исправления после проверки 15 октября

- Фильтр Telegram применяется к API аватаров, стабильным ссылкам на медиа и новому подборщику первого запуска из актуального main. Ответы аватаров разделяют кэш по Cookie, в Telegram используется private/no-store.
- Повторная привязка меняет внутренний id связи TelegramAccount. Старые JWT навсегда теряют доступ, даже после повторной привязки того же аккаунта и очистки кэша. Дополнительной миграции для этого не требуется.
- Реферальная страница в Mini App выдаёт `t.me/<бот>?startapp=ref_<код>`. Новый пользователь получает referredBy, приглашавшему начисляется прежняя реферальная награда сайта (100 realCoins). Подписанный start_param имеет приоритет над параметром ссылки. Повторные входы не меняют пригласившего и не начисляют награду снова. Также поддержаны `/start ref_<код>` и старые `/register?ref=<код>` в Telegram-контексте.
- Экран согласия переключается на проверенный сервером язык Telegram до показа формы, даже когда язык браузера отличается. Язык, явно выбранный ранее пользователем, сохраняет приоритет.
- Подключены safeAreaInset/contentSafeAreaInset и события их изменения: шапка, нижняя навигация и чат учитывают безопасные отступы. Добавлена браузерная проверка ненулевых отступов.
- Обе проверки миграций проверяют наличие своей миграции и её выполнение, допускают последующие миграции. Из main сохранены онбординг, художественный стиль персонажей и последние исправления генерации.
- Перед отправкой проверяется выкладка без новых переменных и без таблиц Telegram: обычный каталог и онбординг работают, Telegram API отвечают 404. При выключенном флаге проверка ежедневного бонуса не обращается к TelegramAccount. В `.env.example` добавлены имена переменных и безопасное значение флага 0.

## Коротко

- Бот работает через webhook `/api/telegram/webhook` с проверкой `X-Telegram-Bot-Api-Secret-Token`. Поддерживаются `/start`, `/start <метка>`, `/start link_<токен>`, `/help` и `/privacy`. Ответы бот отдаёт в теле ответа на webhook, исходящих запросов к Telegram сервер не делает.
- Mini App открывается по адресу `https://<сайт>/tg`. Подпись `initData` проверяется по HMAC-SHA256, затем проверяется срок `auth_date` и отсутствие повторного использования. После этого выдаётся обычная JWT-сессия NextAuth через те же callbacks, что и при обычном входе. Новый пользователь получает те же стартовые VC и тариф, что при регистрации на сайте, и только после явного согласия.
- Существующий аккаунт сайта привязывается из профиля одноразовой ссылкой `t.me/<бот>?start=link_<токен>`, которая действует 10 минут. Отвязка тоже делается в профиле. Аккаунты автоматически не объединяются.
- Признак Telegram-контекста ставит только сервер (httpOnly-cookie после проверенного запуска). В этом контексте скрыты магазин, тарифы, цены, кнопки и ссылки на оплату, а документы с условиями оплаты открываются только во внешнем браузере. API покупок отвечают 403. При нехватке VC показывается «Баланс VC исчерпан». Баланс, ежедневный бонус и рефералы работают.
- Фрагмент `#tgWebAppData` убирается из адреса до запуска Метрики и любых запросов. В адрес подставляется `utm_source=telegram_miniapp` и метка из `startapp`, и они попадают в существующую first/last-атрибуцию.
- В Telegram видны только персонажи из подборки, которую владелец ведёт в `/admin/telegram-catalog`, плюс собственные персонажи пользователя. Фильтр действует в каталоге, поиске, рекомендациях, прямых ссылках, чатах, избранном и гостевом чате.
- Для Telegram Web используется отдельная cookie `SameSite=None; Secure; Partitioned`. Cookie сайта по-прежнему `SameSite=Lax`. В Telegram-контексте встраивание разрешено только доменам Telegram.
- Всё включается флагом `TELEGRAM_MINIAPP_ENABLED`, по умолчанию выключено. В схеме только четыре новые таблицы, существующие таблицы не меняются.

## Решения

### По вопросам владельцу (приняты умолчания задания)

1. **Контент 18+.** В Telegram виден только ручной список владельца (таблица `TelegramCatalogEntry`, страница `/admin/telegram-catalog`). Остальные персонажи там не существуют: страница и чат отдают 404, в списках их нет. Автор всегда видит своих персонажей.
2. **Тестовый бот.** Код не привязан к конкретному боту, все параметры берутся из env. Сначала подключается тестовый бот, после приёмки — боевой (это смена переменных и повтор настройки).
3. **Создание персонажей** в Telegram разрешено. Новые карточки в каталог Telegram не попадают, пока владелец их не отметит. Генерация аватара работает в пределах лимитов. Текст «доступна по подписке…» в Telegram заменён на «Генерация аватара сейчас недоступна.»
4. **Язык.** Если язык уже выбран переключателем (cookie `NEXT_LOCALE`), используется он. Иначе язык берётся из `language_code` Telegram: `ru` → RU, остальное → EN.
5. **Отвязка.** Аккаунт остаётся. Строка `TelegramAccount` сохраняется с `userId = null`, поэтому вход через этот Telegram заблокирован до новой привязки и второй пользователь не создаётся. Сессии, выданные Telegram-запуском, отзываются. Если Telegram — единственный способ входа (аккаунт создан в Mini App), отвязка запрещена, иначе аккаунт осиротеет.

### Технические

- **Точка входа `/tg`.** Прокси отдаёт `/tg` без редиректа на `/ru/tg`, чтобы данные запуска во фрагменте не пришлось нести через лишнюю навигацию. Страница `noindex`: заголовок `X-Robots-Tag` и метаданные. В sitemap её нет.
- **Скрипт запуска** (`src/lib/telegram/launchScript.ts`) — встроенный `<script>` в `<head>`. Он выводится **только в Telegram-контексте**, поэтому разметка обычного сайта не изменилась. Скрипт сохраняет данные запуска под тем же ключом sessionStorage, который читает SDK Telegram (`__telegram__initParams`), и заменяет адрес через `history.replaceState`. Это происходит до гидратации, до Метрики и до первого запроса за ресурсами.
- **Сессия.** `POST /api/telegram/auth` проверяет `initData` и выпускает JWT через `next-auth/jwt`, прогоняя его через `authOptions.callbacks.jwt`: активация отложенной подписки, перенос гостевого чата, признак регистрации для цели `register_success`. Токен кладётся в cookie `__Secure-nv-tg.session-token` (на http-localhost — `nv-tg.session-token`). Прокси подставляет её под имя cookie NextAuth только для запросов с cookie Telegram-контекста. Для `/api` прокси срабатывает **только** при наличии этой cookie (`matcher` с `has: cookie`), так что на API сайта он не влияет.
- **CSRF.** Cookie с `SameSite=None` не защищает от межсайтовых запросов. Поэтому прокси подставляет Telegram-сессию в небезопасные методы (POST/PUT/DELETE и т. п.) только при `Sec-Fetch-Site: same-origin` (или совпадающем `Origin`). Иначе запрос идёт без сессии. Эндпоинты входа и привязки проверяют то же самое сами.
- **Повтор `initData`.** SHA-256 подписи хранится в `TelegramInitDataReceipt`, повторное использование запрещено. Исключение — перезагрузка страницы входа, когда у запроса уже есть сессия того же пользователя: тогда отвечаем «ok», но новую сессию не выдаём.
- **Отзыв сессий.** В JWT, выданном Telegram-запуском, есть `telegramAccountId`. Callback `jwt` проверяет, что аккаунт всё ещё привязан к пользователю (кэш 60 секунд на инстанс). После отвязки сессия перестаёт действовать. При повторной привязке внутренний id меняется, поэтому старые сессии не восстанавливаются.
- **Тема.** Сайт свёрстан только в тёмной палитре (около 170 жёстко заданных цветов). Частичная «светлая» тема дала бы белый текст на светлом фоне. Поэтому интерфейс остаётся в палитре NewVerse, а шапка, фон и нижняя панель Telegram окрашиваются в цвета этой палитры (`setHeaderColor`, `setBackgroundColor`, `setBottomBarColor`). Тема Telegram записывается в `html[data-tg-color-scheme]`, чтобы позже можно было добавить светлый вариант, когда цвета переведут на токены.
- **SDK** `telegram-web-app.js` загружается только в Telegram-контексте. Вызываются `ready()` и `expand()`, вертикальные свайпы отключаются. Системная кнопка «Назад» скрыта на разделах нижней навигации и показана на внутренних страницах. Высота чата следует видимой области над клавиатурой (`--nv-tg-vvh` из `visualViewport`). Внешние ссылки открываются через `openLink` или `openTelegramLink`.
- **Регистрация.** В Telegram `/register` ведёт на `/tg`: аккаунт создаётся входом через Telegram. Согласие там — с Пользовательским соглашением, Политикой и правилами, без оферты (оферта касается покупок). Google в Telegram скрыт на страницах входа и регистрации.
- **Email.** У аккаунтов из Mini App нет email. Баннер «подтвердите email» им не показывается. Для ежедневного бонуса привязанный Telegram засчитывается как подтверждённая личность. Для покупок правило подтверждённого email не меняется.
- **Логи.** Тело запроса входа не логируется. В `redactSensitive` добавлено вычищение `tgWebAppData` и `initData` из текста и JSON. Бот логирует только имя команды.

## Схема и SQL

Файл `prisma/migrations/20261014180000_telegram_miniapp/migration.sql`.
- Только `CREATE TABLE IF NOT EXISTS`, индексы и внешние ключи на новых таблицах. Внешние ключи пересоздаются парами `DROP CONSTRAINT IF EXISTS` + `ADD CONSTRAINT`.
- Файл можно выполнять повторно. В комментариях нет `;`, поэтому Adminer выполняет его как есть.
- Существующие таблицы не меняются. Код безопасно выкладывать и **до** применения SQL при выключенном флаге: новые таблицы читаются только Telegram-кодом.

| Таблица | Назначение |
|---|---|
| `TelegramAccount` | `telegramId` (уникальный, строкой), `userId` (уникальный, nullable, `ON DELETE SET NULL`), `origin` (`telegram`/`site`), `linkedAt`, `unlinkedAt`, `lastLoginAt` |
| `TelegramLinkToken` | `tokenHash` (SHA-256, уникальный), `userId` (`ON DELETE CASCADE`), `expiresAt`, `usedAt` |
| `TelegramInitDataReceipt` | `hash` (SHA-256 подписи), `expiresAt`. Устаревшие строки удаляются при следующем входе |
| `TelegramCatalogEntry` | `characterId` (PK, `ON DELETE CASCADE`), `addedById`, `createdAt` |

Откат схемы: `prisma/sql/telegram-miniapp-rollback.sql`. Обычный откат — флагом, таблицы остаются.

## Переменные окружения (только имена)

| Имя | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_MINIAPP_ENABLED` | да, `1` для включения | Mini App, вход через Telegram, webhook, привязка. Без неё всё отвечает 404 |
| `TELEGRAM_BOT_TOKEN` | да | Ключ для проверки подписи `initData` |
| `TELEGRAM_WEBHOOK_SECRET` | да | `secret_token` webhook: 24–256 символов `A-Z a-z 0-9 _ -` |
| `TELEGRAM_BOT_USERNAME` | да | Имя бота без `@` для ссылок `t.me` в профиле |
| `TELEGRAM_INITDATA_MAX_AGE_SECONDS` | нет | Срок `auth_date`, по умолчанию 3600 |

`NEXTAUTH_URL` должен быть `https://…`: от него зависят имена cookie с `__Secure-` и адреса в кнопках бота.

## Инструкция владельцу

Все шаги во внешних сервисах выполняет владелец сам, в своём браузере и под своей учётной записью. Токены и секреты в чат не присылать.

**1. @BotFather (Telegram), сначала тестовый бот**
1. `/newbot` → имя и username, например `newverse_test_bot`. Токен сохранить у себя, в чат не присылать.
2. `/mybots` → бот → **Bot Settings → Configure Mini App → Enable Mini App**, URL: `https://<домен>/tg`. При желании задать короткое имя через **/newapp**, тогда будут работать ссылки `t.me/<бот>/<имя>?startapp=метка`.
3. `/setjoingroups` → **Disable**: бот работает только в личных сообщениях.
4. Описание и картинку — по желанию. Не упоминать в них покупки и цены.

**2. Локальная проверка (по желанию)**
Записать в локальный `.env` переменные `TELEGRAM_MINIAPP_ENABLED=1`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (случайная строка от 32 символов) и `TELEGRAM_BOT_USERNAME`. Telegram требует HTTPS, поэтому полную проверку на телефоне удобнее делать на тестовом окружении. Туннель для HTTPS без вашего согласия не ставил.

**3. SQL через Adminer**
Выполнить `prisma/migrations/20261014180000_telegram_miniapp/migration.sql` целиком. Затем проверить:
```sql
SELECT table_name FROM information_schema.tables WHERE table_name LIKE 'Telegram%' ORDER BY 1;
```
Должно быть 4 строки.

**4. Relaxdev → переменные**
Добавить переменные из таблицы выше (флаг пока `0` или не задан) и выложить код. Затем поставить `TELEGRAM_MINIAPP_ENABLED=1` и перезапустить.

**5. Webhook, команды и кнопка меню** — на своей машине, с переменными тестового бота:
```bash
node --env-file=.env scripts/telegram-bot-setup.mjs --site https://<домен>
```
Без `--apply` скрипт только показывает план: `setWebhook` на `/api/telegram/webhook` с `secret_token` и `allowed_updates: ["message"]`, команды RU/EN, кнопку меню «NewVerse» → `/tg`. Если план верный, выполнить с `--apply`. Проверка: `--info` (ничего не меняет). Токен и секрет скрипт не печатает.

**6. Подборка персонажей**
Открыть `https://<домен>/ru/admin/telegram-catalog` под своим аккаунтом, ввести ключ администратора и отметить персонажей для Telegram. Пока подборка пуста, каталог в Telegram пустой.

**7. Боевой бот** — после приёмки на тестовом: повторить шаги 1, 4 и 5 с его токеном и username.

Что покрывают проверки (по пунктам приёмки):

1. **initData.** Правильная подпись проходит, Telegram id больше 2^53 сохраняется точно. Отклоняются: подпись чужим токеном, подмена `user` и `start_param`, просроченный и будущий `auth_date`, повтор поля, битый или пустой `hash`, бот вместо человека. Повтор того же `initData` без сессии → 401. Перезагрузка со своей сессией принимается без новой сессии. Подделка не получает никаких cookie. Межсайтовый запрос → 403.
2. **Первый вход** — только после согласия; до согласия ничего не создаётся и не расходуется. Пользователь получает стартовые VC, тариф `start` и транзакцию `signup_bonus`, как при регистрации на сайте. Повторный запуск находит того же пользователя без второго бонуса. Два параллельных первых запуска создают одного пользователя. Сессия — обычный JWT NextAuth. Через прокси `/api/auth/session` видит пользователя. Цель регистрации отмечается один раз, повторный запуск — это вход, а не регистрация.
3. **Привязка.**
   - Ссылка `t.me/<бот>?start=link_<токен>`; в БД хранится только хэш токена.
   - Токен одноразовый, истекает, привязан к своему пользователю, у пользователя одновременно действует не больше одного токена.
   - Telegram, уже создавший своего пользователя, не объединяется: понятное сообщение, данные не меняются.
   - Привязка начинается только на сайте, межсайтовые запросы отклоняются.
   - Отвязка сохраняет аккаунт и баланс и отзывает Telegram-сессии. Следующий запуск получает «вход отключён», нового пользователя нет.
   - Отвязать единственный способ входа нельзя. Новая привязка возвращает вход.
4. **Webhook** без секрета или с неверным секретом → 401 без побочных эффектов (токен привязки не израсходован). Флаг выключен → 404. Бот: `/start`, `/start <метка>`, `/help`, `/privacy`, группы игнорируются. В ответах нет цен и ссылок на оплату.
5. **Без покупок.**
   - Обход 31 адреса в Telegram-контексте (SSR-HTML) и 10 страниц в браузере после загрузки данных (RU и EN, тёмная и светлая тема): нет цен, «Купить», ссылок на `/coins`, `/pricing`, `/subscription`, `/offer`, `/refund`, Robokassa и платёжные API, нет `data-action=*checkout`.
   - `/coins` — нейтральная страница «Баланс VC» с бонусом. `/terms` и `/privacy` открываются только через `openLink`. `/register` ведёт на вход через Telegram.
   - API покупок → 403 с нейтральным текстом. При нехватке VC — «Баланс VC исчерпан».
   - Баланс виден и не ведёт в магазин. Нижняя навигация без «Монет». В профиле нет блока подписки и есть ежедневный бонус, который начисляется без email.

6. **Приватность.**
   - Адрес после загрузки без `tgWebAppData`.
   - Метрика ни в загрузке счётчика, ни в `init`, `hit` или целях не получает `tgWebAppData`, Telegram id и имя.
   - Ни один запрос и ни один `Referer` не содержит данных запуска.
   - `analyticsUrl` и вычищение логов удаляют их из любого адреса и тела.
7. **Атрибуция.** Первое обращение к Метрике несёт `utm_source=telegram_miniapp` и `utm_campaign` из `startapp`; тот же адрес записывается в first/last-атрибуцию. Метка из `/start <метка>` передаётся через кнопку бота. `register_success` срабатывает ровно один раз, в том числе после перезагрузки.
8. **Фильтр контента.**

   - Прямые ссылки на скрытого персонажа (страница и чат) → 404, имя не раскрывается.
   - На сайте всё как раньше.

Чужой сайт встроить приложение не может (`frame-ancestors`). Межсайтовая запись с Telegram-cookie остаётся без сессии.

## Порядок выкладки и откат

1. Код с выключенным флагом (`TELEGRAM_MINIAPP_ENABLED` не задан). Сайт работает как раньше: прокси без Telegram-cookie ведёт себя по-прежнему, новые таблицы не читаются.
2. SQL миграции через Adminer.
3. Переменные бота в Relaxdev, затем флаг `1`.
4. Подборка `/admin/telegram-catalog`, webhook и кнопка меню (скрипт настройки), проверка на телефоне по чек-листу.

**Откат:** `TELEGRAM_MINIAPP_ENABLED=0` и перезапуск. Webhook, вход через Telegram и привязка отвечают 404, Telegram-сессии больше не подставляются прокси. Покупки у тех, кто уже открывал Mini App, остаются скрытыми: cookie контекста продолжает действовать. Схему откатывать не нужно. Чтобы бот перестал принимать сообщения: `deleteWebhook` или повтор настройки после исправления.

## Чек-лист для ручной проверки (iPhone, Android, Telegram Desktop, Telegram Web)

Для каждого клиента, через тестового бота:
1. `/start` → приветствие и кнопка «Открыть NewVerse». `/help` и `/privacy` открывают правила и политику в браузере.
2. Первый запуск → экран согласия → «Продолжить» → каталог. В каталоге только отмеченные персонажи. Баланс VC показывает стартовые VC.
3. Шапка и фон Telegram тёмные в светлой и тёмной теме Telegram. Текст читается.
4. Нигде нет «Монет», «Подписки», цен в ₽, кнопок «Купить» и ссылок на оплату: главная, профиль, чат, создание, уведомления, рефералы, поддержка, меню. Прямой адрес `/ru/coins` показывает «Баланс VC» и ежедневный бонус.
5. Ежедневный бонус начисляется.
6. Чат: сообщение, «Продолжить», новая история. При открытой клавиатуре поле ввода видно (iOS!). Свайп вниз по ленте не закрывает приложение.
7. На странице персонажа есть системная «Назад», на разделах её нет. «Назад» возвращает на предыдущую страницу.
8. Ссылка `t.me/<бот>?startapp=c_<slug>` открывает этого персонажа, `?startapp=метка` — каталог.
9. Привязка: на сайте в профиле «Привязать Telegram» → в Telegram «Запустить» → «Telegram привязан». В Mini App тот же аккаунт и баланс, что на сайте. Отвязка на сайте → следующий запуск показывает «Вход через Telegram отключён».
10. Telegram Desktop и web.telegram.org: вход проходит, после перехода по страницам сессия сохраняется.
11. Метрика (через 1–2 часа): визит с источником `telegram_miniapp` и меткой. В отчёте «Адреса страниц» нет `tgWebAppData`.
12. Реферальная ссылка из Mini App открывает `startapp=ref_<код>`: после согласия приглашённый учитывается в статистике, награда начисляется один раз.
13. После отвязки и повторной привязки старая открытая сессия не восстанавливается. Новый запуск получает новую сессию.
14. При смене ориентации и размеров окна шапка, нижняя навигация и поле чата не перекрываются элементами Telegram или системными областями экрана.

## Что не проверено и ограничения

- Реальные клиенты Telegram, HTTPS, настоящий webhook — проверяет владелец по чек-листу.
- Аккаунт, созданный в Mini App, не может войти на сайт: у него нет email, пароля и Google. Вход на сайт через Telegram Login Widget — отдельная задача (нужен домен в @BotFather).
- Рефералы через `startapp=ref_<код>` реализованы и проверены изолированно. Реальные переходы через Telegram остаются в ручной приёмке.
- Светлая тема интерфейса не сделана, см. «Тема».
- Кэш отзыва сессий — 60 секунд на инстанс. На другом инстансе отвязка действует не сразу, а в пределах этой минуты.
- Обычный сайт по-прежнему не запрещает встраивание во фреймы. Ограничение `frame-ancestors` добавлено только в Telegram-контексте. Глобальное `frame-ancestors 'self'` стоит обсудить отдельно: карта кликов Метрики показывает сайт во фрейме.
