# Поддержка нескольких языков

## Что подготовлено

Один реестр `public/locales/manifest.json` управляет доступными языками, их названиями, форматом дат и чисел, направлением текста, резервным языком и языком ответов ИИ. В коде включены русский, английский и испанский. Новые языки создаются выключенными, чтобы черновик перевода не появлялся у пользователей.

Интерфейс, письма, серверные сообщения, SEO, тексты главной страницы и жанров используют `public/locales/<код>/common.json`. Адреса, переключатель, sitemap, hreflang, IndexNow, Telegram и поиск персонажей учитывают общий список языков. При переключении сохраняются параметры страницы и якорь. Язык чата берётся из явного заголовка запроса, затем сохранённого выбора, затем настроек браузера.

Для переводов персонажей добавлена таблица `CharacterTranslation`: одна запись на персонажа и язык. Новые языки не требуют новых колонок базы. Старые поля `*_en` продолжают работать. В таблице нет приватной памяти и системных инструкций. При изменении исходных полей переводы удаляются в том же обновлении; изменения счётчиков и активности их не сбрасывают. Изменение только `*_en` сбрасывает только новую английскую запись.

## Добавить язык

Например, подготовить немецкий:

```sh
npm run i18n:add -- --locale=de --label=Deutsch --language-name=German --intl=de-DE
```

Команда создаст `public/locales/de/common.json` из английского исходника и выключенную запись в реестре. Это **заготовка, а не готовый немецкий перевод**. Для арабского или иврита указать `--direction=rtl`. Для региональных вариантов использовать канонический код, например `pt-BR`.

Перевести словарь, сохранив имена ключей, переменные `{{name}}`, `{{count}}` и другие, разметку ссылок и структуру списков. Категории множественного числа заготовка создаёт с учётом нового языка. Проверить в том числе `landing`, `genreIntros`, `characterTags`, `telegramBot`, `globalError` и SEO-описания. Названия и количество поддерживаемых языков в рекламных текстах также требуют редакторской проверки.

Проверить черновики:

```sh
node scripts/i18n-check.mjs --all
```

После проверки текстов изменить `enabled` на `true` в реестре и выполнить:

```sh
npm run i18n:sync
npm run i18n:check
npm run verify:i18n
npm run typecheck:app
```

`i18n:sync` обновляет генерируемые ресурсы и небольшие тексты корневой страницы ошибки. Он автоматически запускается перед `dev` и `build`. `i18n:check` проверяет ключи, пустые значения, переменные и формы множественного числа, а не качество самого перевода. Проверка перевода человеком остаётся необходимой. Не редактировать `*.generated.ts` вручную.

## Перевести каталог

После применения миграции проверить объём работы без платных запросов:

```sh
npm run translate:characters:locale -- --locale=de --limit=50
```

Выполнить перевод и сохранить результат:

```sh
npm run translate:characters:locale -- --locale=de --limit=50 --apply
```

Требуются действующие `DATABASE_URL`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`. Провайдер должен поддерживать выбранный код языка. Поддержка конкретного языка моделями чата и озвучки проверяется отдельно.

По умолчанию обрабатываются публичные персонажи. Для одного персонажа можно указать `--id=<id>`. Повторный запуск пропускает актуальные переводы по отпечатку исходных полей; `--force` создаёт их заново. Лимит относится к требующим перевода персонажам, а не к первым записям базы. Не запускать одновременно несколько оплачиваемых обработок одного языка: команда защищает целостность результата, но не предотвращает повторную оплату запросов независимыми процессами.

Перевод сохраняется целиком только после успеха всех полей. Если персонаж изменился, пока провайдер готовил перевод, результат не записывается. Приватная память не отправляется этим обработчиком на перевод и не попадает в публичные ответы.

После создания или редактирования персонажей обработчик нужно запускать повторно, например как отдельную задачу инфраструктуры. Автоматическое платное создание всех переводов в пользовательском запросе не включено. До готовности перевода карточка использует резервный язык. Существующий автоматический перевод в `*_en` сохранён.

Юридические страницы со статическим русским текстом в этот перевод не входили.

Испанский включён в реестре кода. На опубликованном сайте он появится после публикации этих изменений.

Для этой операции рабочая база была доступна через Adminer, а локальный `DATABASE_URL` указывает на другую базу. Поэтому использован пакетный обработчик без прямого подключения к базе:

```sh
npm run translate:pack -- --locale=es --catalog=.runtime/localization/catalog-public-2026-10-28.json --review=scripts/data/spanish-character-review.json
npm run translate:pack -- --locale=es --catalog=.runtime/localization/catalog-public-2026-10-28.json --review=scripts/data/spanish-character-review.json --max-characters=800000 --apply
```

Первая команда только рассчитывает объём. Вторая отправляет недостающие сегменты в Yandex Translate, сохраняет промежуточные результаты и создаёт `.runtime/localization/import-es.sql`. Экспорт каталога должен содержать только `id`, `isPublic=true` и поля из `CHARACTER_TRANSLATION_FIELDS`; лишние поля, включая приватную память, отклоняются. JSON с готовыми переводами и исходниками остаётся в игнорируемой папке `.runtime`.

`--max-characters` ограничивает объём недостающих сегментов текущего запуска. Дополнительно `--max-total-characters` ограничивает суммарный объём с учётом предыдущих попыток из кеша. Объём запроса сохраняется до обращения к провайдеру: даже тайм-аут не обнуляет возможный расход. Отклонённые и неподтверждённые запросы отмечаются в квитанции отдельно; итоговая оценка консервативна и не заменяет счёт провайдера. HTTP 429 требует дождаться восстановления квоты или её официального увеличения, а не повторять запросы без ограничения.

Перед переводом защищаются переменные, разметка, переносы строк, ссылки и названия сервисов. При повторном запуске готовые сегменты берутся из сохранённого кеша. Проверенные строки из `reviewed.json` не отправляются на повторный перевод. Готовый SQL проверяет, что карточка всё ещё публичная и исходные поля не изменились, и только затем обновляет перевод; изменившиеся записи пропускаются. Повторный импорт обновляет существующие записи по ключу `(characterId, locale)`.

В Yandex выполнено 83 запроса, отправлено 723152 символа с учётом служебной HTML-разметки. Расчёт по тарифу 500,4 ₽ за миллион — 361,87 ₽; это оценка, а не подтверждённый счёт провайдера. В `AiCostEvent` сохранена одна агрегированная запись этой операции, без повторного списания и без пользовательских VC. Повторная сборка пакета после редакторских исправлений прошла из кеша, без дополнительных платных запросов.

## Резервный язык и проверка выпуска

### Меню выбора языка

В шапке и подвале остаётся одна кнопка с кодом текущего языка. На компьютере она открывает меню с одним столбцом; на телефоне — панель снизу. В мобильном боковом меню и меню профиля используется тот же компонент. Список берётся из включённых языков `manifest.json`; поиск понимает код, родное и переведённое название языка, а также ввод без диакритики. Длинный список прокручивается внутри панели. Escape, кнопка закрытия и нажатие снаружи закрывают меню; фокус возвращается на кнопку.

Пункт «Автоматически» записывает `NEXT_LOCALE_AUTO=1` на год. При входе по адресу без языкового префикса язык снова определяется по `Accept-Language`; переходы на локализованные страницы не заменяют эту настройку. В `NEXT_LOCALE` сохраняется фактический язык страницы: это также сохраняет язык ошибок API при открытии явной ссылки на другом языке. Ручной выбор записывает конкретный код и выключает автоматический режим (`NEXT_LOCALE_AUTO=0`), включая повторный выбор уже открытого языка. Язык в явной ссылке остаётся приоритетным. Переключение сохраняет путь страницы, параметры и якорь. Новые посетители без сохранённого выбора при входе по адресу без префикса остаются в автоматическом режиме. Старые сохранённые значения `ru`, `en`, `es` продолжают работать.

`npm run verify:i18n:menu` проверяет настоящий компонент, словари и стили в отдельном тестовом браузере: выбор и автоматический режим, поиск, клавиатуру, мобильные экраны, прокрутку и сценарий с десятью языками. Сценарий с десятью языками использует отдельный тестовый реестр и не включает черновые языки в проекте. Сборка Next.js, рабочая база и внешние запросы для этой проверки не нужны.

Порядок резервных переводов задаётся в реестре; циклы завершаются без зацикливания. Сервер и браузер используют одинаковый порядок. Русский исходник остаётся последним резервом. Настройка `languageName` задаёт язык ответа чата независимо от языка описания персонажа или старых сообщений. Внутренние инструкции и подписи контекста могут оставаться русскими или английскими: пользовательский язык ответа задаётся отдельно.

Перед включением языка проверить `/de`, каталог и поиск по переведённому имени, карточку, создание персонажа, вход и восстановление пароля, первый ответ и продолжение чата, оплату и Telegram. Для RTL отдельно проверить расположение элементов: установка `dir=rtl` сама по себе не гарантирует правильный вид всех компонентов. Платёжный шлюз сохраняет собственный выбор RU/EN; для остальных языков сайта используется английский.

Полная локализация нового языка означает перевод словаря и каталога, проверку оставшихся старых строк вне словарей, юридических текстов, пользовательского контента и качества моделей. Подготовленный механизм не переводит их автоматически и не является обещанием качества для любого языка.

## Проверки подготовки

Проверены реальная маршрутизация и инструкции чата на тестовых немецком и арабском, серверные и клиентские резервные переводы, независимость одновременных языковых экземпляров, права доступа к приватной карточке, сброс устаревших переводов, миграция на одноразовой базе и команды подготовки нового языка. Штатная компиляция Webpack в текущем окружении останавливается внутри `FileSystemInfo`/`WasmHash` (`Cannot read properties of undefined (reading 'length')`). Полная проверка TypeScript также захватывает существующие Canvas-черновики из `docs`, в которых не находится `cursor/canvas`; `typecheck:app` отдельно проверяет код приложения. В lint изменённых файлов остаётся существующая ошибка `set-state-in-effect` на странице профиля; новые модули многоязычности проверяются без ошибок. Перед выпуском нужно устранить или отдельно решить эти общие ограничения проверки проекта.
