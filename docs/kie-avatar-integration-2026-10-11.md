# Генерация изображений Kie AI — 11 октября 2026

## Результат и границы

В рабочей копии генерация аватаров и обложек переведена с Createya на Kie. Модель выбирает сервер: текст → `seedream/5-flash-text-to-image` (Seedream 5.0 Flash), валидный референс → `nano-banana-2-1` (Nano Banana 2.1). Клиентские `modelId`, разрешение и число изображений не управляют тарифом. Обе модели используют 1K, PNG у провайдера, вертикальное 3:4. Стили «Аниме»/«Реалистичный» сохранены.

В редакторе удалены карточки выбора модели. Референс перенесён из общих расширенных настроек в раскрываемый блок рядом с генерацией. В интерфейсе показаны «Генерация по описанию» / «Генерация по референсу», без выбора провайдера. Референс необязателен.

Production-БД, ключи, баланс Kie и платные генерации в рамках реализации не использовались. Коммит, push и деплой не выполнялись. Параллельные изменения других задач не включаются в область этого отчёта.

## Асинхронный процесс

- `POST /api/generate-avatar`: проверка сессии, ограничение тела (в том числе chunked), имени, scope/clientKey и референса; локальная подготовка промпта; резервирование одной генерации; создание задачи Kie; сохранение `taskId`; ответ 202.
- `GET /api/generate-avatar?jobId=…` или `?scope=…`: только задачи текущего пользователя; сверка Kie и текущий лимит. Чужой jobId возвращает 404. Ответы запрещают кеширование.
- `AvatarGeneration` хранит scope, ключ повторного запроса, хеш параметров, модель, taskId, состояния, результат и параметры себестоимости. Тексты промптов и референсы в этой таблице не сохраняются.
- Транзакция с блокировкой `User` объединяет резервирование лимита и создание записи задачи. Повтор clientKey с тем же хешем возвращает прежнюю задачу; изменённый запрос — 409. Вкладки сериализуются: одновременно допускается одна незавершённая задача на пользователя. Другая карточка получает понятное сообщение 409.
- Проверка результата имеет lease/token и проверку владельца перед завершением. Сохранение изображения, финальное состояние и расчёт возврата квоты выполняются одной транзакцией. Поздний работник не завершает чужой lease.
- Подтверждённая ошибка задачи или явный отказ создания возвращают одну генерацию. Повтор проверки не возвращает её второй раз; старый месяц/сброс лимита при активации подписки защищены.
- Обрыв создания, 5xx, отсутствие taskId при HTTP 200 и перезапуск до фиксации taskId считаются неопределённым результатом: резерв остаётся `manual_review`, повторный платный запрос блокируется. Поддержке потребуется сверка с кабинетом Kie. Лог принятия задачи содержит только taskId/jobId/model, чтобы восстановить связь при ошибке записи в БД.
- Ошибка проверки или скачивания не означает ошибку оплаченной генерации: taskId сохраняется, повторяется проверка/скачивание, а не создание новой задачи.

## Результат и редактор

Ссылки провайдера временные. Изображение скачивается с разрешённых доменов Kie (`redpandaai.co`, `aiquickdraw.com`, `kie.ai` и их поддомены), без перенаправлений, с ограничением 10 МБ и 16 млн пикселей. После декодирования преобразуется в WebP, до 1536 px, и сохраняется в БД как data URL — как существующие изображения проекта. Клиент не управляет URL скачивания.

Референс принимается только как растровый data URL до 5 МБ, декодируется Sharp, нормализуется в PNG до 1536 px и загружается через отдельный Kie File Upload API. SVG и произвольные ссылки не принимаются. Случайное имя загрузки исключает перезапись чужого референса.

Редактор сохраняет ключ незавершённого POST в sessionStorage с привязкой к аккаунту и scope; при запрете storage действует память вкладки. Незавершённая задача восстанавливается через сервер после reload. Уже готовое историческое изображение предлагается восстановить отдельной кнопкой, чтобы не подменять новый черновик. Смена аккаунта/карточки/типа размонтирует предыдущую обработку и отменяет запросы. Цель `generate_avatar` вызывается при применении готового результата; в пределах доступного sessionStorage повторное восстановление той же задачи не отправляет её повторно. Межвкладочный exactly-once для этой цели не заявляется.

## Фоновая обработка и безопасность

`/api/cron/reconcile-avatars` проверяет до трёх задач за вызов. Существующая авторизация `CRON_SECRET`: Bearer или `x-cron-secret`; сохраняется совместимость с query secret. В ответе/логе только counts, включая число задач, требующих ручной сверки. Cron нужен, чтобы закрыть результат без открытой страницы редактора.

Дополнительно поддержан `/api/webhook/kie`. Он используется только при настроенном `KIE_WEBHOOK_HMAC_KEY`. Подпись: Base64 HMAC-SHA256 от `taskId.timestamp`, constant-time сравнение и окно 5 минут. Подпись покрывает только идентификатор/время, поэтому состояние, URL и стоимость из callback не принимаются на веру: сервер сам получает `recordInfo`. Без HMAC используются клиентский опрос и cron.

API-ключ берётся только на сервере через `process.env['KIE_API_KEY']`, что совместимо с отсутствием заглушек optional env на Relaxdev. Заголовки авторизации не отправляются на CDN. Ошибки провайдера преобразуются в фиксированные категории, клиент и логи не получают исходные тела/промпты/ключи. Проверяется JSON `code`, а не только HTTP 200.

## Экономика

Пользовательская квота неизменна: любая из двух моделей расходует одну генерацию. Месячные лимиты продолжают рассчитываться из прежнего бюджета 5 ₽/генерацию и 10% стоимости подписки; снижение предполагаемой цены провайдера автоматически не увеличивает обещанный лимит.

Одна задача — одна запись `AiCostEvent` с provider=`kie`, apiSurface=`image_generation`, accountingVersion=2 и связью с резервом. Фактическое поле `creditsConsumed` сохраняется как `providerCostNative`, валюта `CREDIT`, семантика `reported_credits_consumed`. RUB = кредиты × 0,5 (согласованное владельцем 2 кредита за 1 ₽), источник `kie_credits_estimate`. Это оценка приобретения кредитов, не подтверждённое рублёвое списание: `reportedCostRub=null`.

Если число кредитов отсутствует, для успешно сохранённой картинки применяется только конфигурационная оценка: Seedream 3,24 кредита, Nano Banana 4 кредита. Неизвестные/неуспешные задачи без credit usage не становятся бесплатными. Отчёт затрат принимает новый источник оценки и не смешивает его с подтверждённым журналом KodikRouter. Устаревший pending writer не перезаписывает terminal cost event. Старые записи Createya сохранены.

## Выкладка

Сначала свежий бэкап Timeweb и scoped SQL одной транзакцией, затем код. В production нет истории `_prisma_migrations`: полный `prisma migrate deploy` для старой цепочки не запускать. SQL создаёт только таблицу `AvatarGeneration`, её FK и пять индексов.

Ключ уже добавлен владельцем на Relaxdev, баланс заявлен 1051 кредит; ни доступность ключа из контейнера, ни реальные списания в этой реализации не проверялись. После выкладки нужны cron раз в минуту и две живые проверки: текст и референс, с сопоставлением taskId/creditsConsumed в кабинете и БД. Optional HMAC требует одинакового ключа в Kie Settings и `KIE_WEBHOOK_HMAC_KEY` на Relaxdev. Миграция и production-проверки ещё не выполнены.
