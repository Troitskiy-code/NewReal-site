# Распознавание говорящих в сцене

Первый этап интерактивной новеллы, 03.11.2026. Пользователь выбрал **только распознавание с просмотром результата**. Назначение разных голосов и сборка аудио в этот этап не входят.

## Поведение

У сохранённого ответа доступна кнопка **«Кто говорит?»**. Она показывает дословные фрагменты и их авторов: рассказчик, основной герой, участники группы или NPC. Неоднозначная прямая речь помечается **«Говорящий неясен»**. У каждого фрагмента сохранены координаты в нормализованном исходнике, тип «речь/повествование» и уверенность назначения.

Режим выбирается по настройкам конкретной истории с приоритетом над карточкой:

- `character`: основной герой и возможные случайные NPC;
- `group`: участники `rpConfig.participants` с их существующими ID, профилями и возможные NPC;
- `world`: рассказчик и NPC; название мира не становится говорящим.

Модель получает текущий ответ и до шести предыдущих сообщений (до 1200 символов каждое), краткую карточку, состав группы, описание NPC и известные имена говорящих этой истории. Персона игрока не объявляется NPC. Прямая речь внутри повествования выделяется отдельно; меню выбора и короткие ремарки исключаются.

При прослушивании продолжает использоваться один выбранный голос. Разметка пока создаётся отдельным действием и не заменяет действующую подготовку озвучки. Она не запускает Kie и не расходует дневное прослушивание.

## Хранение и границы

- `Message.speechRecognition`: результат или кратковременная аренда подготовки. Результат содержит отпечатки исходника и контекста, роли и точные фрагменты. Редактирование исходного ответа или изменение режима/состава/контекста делает серверный кеш неактуальным.
- `ChatThread.speechCast`: до 64 NPC с постоянными ID. Реестр приватный и не переносится между историями. Время первого появления не позволяет подмешивать в старую сцену имена, появившиеся позднее.
- Полная очистка истории сбрасывает её реестр NPC. Обычная загрузка переписки не передаёт внутреннюю разметку и аренды подготовки вместе со всеми сообщениями: результат запрашивается отдельным действием.
- Именованный NPC получает стабильный ID по нормализованному имени; модель может использовать прежний ID при возвращении героя. У главного героя учитывается английское имя-алиас. Полного разрешения всех псевдонимов и склонений на сервере нет: для них используется контекст модели.
- У безымянного NPC новый ID привязан к сообщению, чтобы автоматически не отождествлять двух разных охранников. Для повторного использования прежнего ID модель должна связать героя с ближайшим контекстом.
- Сервер принимает только последовательные неперекрывающиеся подстроки источника, известные ID либо новых NPC с дословным подтверждением имени. Это проверяет целостность разметки, но не является доказательством правильности всех смысловых назначений.
- До 64 фрагментов, до 8000 символов выбранной речи, исходник до 16000 символов. Новый NPC должен быть подтверждён материалами; неуверенное назначение возвращается рассказчику с явной отметкой неопределённости.
- Подготовки сериализуются по аккаунту; аренда 90 секунд. Вызов модели ограничен 50 секундами. Ошибка освобождает только свою аренду; редактирование или удаление ответа во время подготовки не публикует старый результат.
- Ответ API приватный, `no-store`. Проверяются авторизация, доступ к карточке, владелец истории/сообщения и источник POST-запроса. Не более 10 новых распознаваний в минуту на аккаунт; повтор готового результата не вызывает модель.

Результат раскрывается после нажатия кнопки. После перезагрузки кнопка повторно получает сохранённую разметку без нового вызова модели. После изменения режима истории уже открытый локальный просмотр обновляется следующим нажатием.

## API и реализация

`GET /api/chat/:id/speech/recognition?thread=...&messageId=...` возвращает сохранённую актуальную разметку или `null`, без вызова модели.

`POST` на тот же адрес создаёт разметку либо возвращает готовую. Текст, список героев, модель и параметры провайдера читаются только на сервере, из запроса они не принимаются.

Модель: существующий Mistral Small 3.2 в DeepInfra. Назначение операции в `AiCostEvent` — `speech_recognize`, отдельно от `speech_prepare`. Нужен существующий `DEEPINFRA_API_KEY`.

## Проверки

`npm run verify:speech` проверяет прежнюю озвучку и новый этап на отдельном PostgreSQL с искусственными аккаунтами и подставными платными сервисами. В набор добавлены режимы character/group/world, NPC, местоимения через известный ID, неоднозначные назначения, дословность, повторяющиеся фразы, англоязычный алиас, посторонняя история/аккаунт, кеш, гонки, редактирование, смена режима и работа при исчерпанном лимите прослушивания. Проверяется реальная SQL-миграция. Эти тесты не измеряют семантическую точность модели.

Итог: **201 проверка прошла**. Также прошли TypeScript-проверка приложения, ESLint изменённых модулей и проверка всех 11 словарей интерфейса. Аналитические `docs/**/*.canvas.tsx` исключены из общей TypeScript-проверки приложения: их SDK относится к просмотру материалов, а не к сайту.

Финальная production-сборка `next build --webpack` прошла с уже обновлённым Prisma Client и чистым локальным кешем Webpack. На этой Windows-среде повторное использование кеша воспроизводило сбой `WasmHash`; кеш перемещён в резервные папки внутри `.runtime`, исходники сборщика не менялись. Рабочий сайт не публиковался.

`node scripts/probe-scene-speakers.mjs --live` — отдельная ограниченная проверка на семи искусственных сценах с реальной моделью. Она не подключается к БД проекта и не вызывает TTS. Без `--live` сетевых вызовов нет. Ключ читается из локальных настроек без вывода в журнал.

Живая проверка 03.11: первоначально 6/7; неизвестный голос внутри повествования ошибочно остался частью narration. После уточнения инструкции все 7/7 сцен прошли: одиночный герой с NPC, группа, вселенная, возвращение NPC по местоимению, неизвестный голос, сцена с меню, английский диалог. Последний набор занял 3,7–5,8 секунды на сцену; reported estimated_cost набора — $0,000798075. Обе серии суммарно — около $0,00151. Это небольшой контрольный набор, а не оценка точности на всех историях или фиксированная цена операции.

Машинный результат: [живой контрольный набор](scene-speaker-recognition-probe-2026-11-03.json). В нём только искусственные тексты.

## Включение

До публикации новой версии применить только подготовленную добавочную миграцию:

[20261103120000_scene_speaker_recognition](../prisma/migrations/20261103120000_scene_speaker_recognition/migration.sql).

Она добавляет два nullable JSONB-поля без изменения существующих строк. Сначала проверить их отсутствие, затем применить SQL в транзакции с ограничением времени блокировки и обновить Prisma Client. Для рабочей БД не использовать `db push` и не запускать все исторические миграции; действующий порядок проекта — отдельные проверенные SQL-изменения.

`CHAT_SPEAKER_RECOGNITION_ENABLED=false` скрывает действие и выключает API. Сам флаг не устраняет необходимость миграции при публикации нового Prisma Client: код разрешения истории читает модель `ChatThread` целиком.

03.11.2026 миграция применена к рабочей БД через Adminer после создания физической резервной копии Timeweb от 19:52 МСК. Два поля добавлены одной транзакцией с lock_timeout=5s и statement_timeout=30s; повторный независимый запрос подтвердил JSONB, nullable и отсутствие изменений существующих значений. История Prisma не создавалась. Подтверждение сохранено локально в `docs/scene-speaker-migration-production-2026-11-03.jpg`.

В тот же день подготовка озвучки получила отдельную политику: в одиночном чате озвучиваются только произнесённые слова, во вселенной/группе сохраняется повествование. Разметка «Кто говорит?» по-прежнему показывает состав сцены; разные голоса на этом этапе не назначаются. Подробности: [озвучка персонажей](character-speech-2026-10-19.md).
